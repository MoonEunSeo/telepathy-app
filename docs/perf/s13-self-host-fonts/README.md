# S13. 웹폰트 자체 호스팅

> 조건: **production build / localhost:5000 / Lighthouse 12 CLI (headless) / 5회**
> Before 는 같은 세션에서 변경분을 `git stash` 하고 다시 빌드해 측정했다.
> [S11](../s11-code-splitting/README.md) 과 달리 **폰트를 차단하지 않았다** — 외부 오리진을
> 없애는 것이 이번 변경의 내용이므로, 차단하면 효과가 보이지 않는다.

## 무엇이 문제였나

`fonts.googleapis.com` 의 CSS 를 받고, 거기 적힌 주소로 `fonts.gstatic.com` 에서 woff2 를 받고 있었다. 오리진 두 곳에 각각 DNS·TCP·TLS 가 필요하다.

[S11](../s11-code-splitting/README.md) 에서 이 외부 의존이 측정을 망쳤다. Lighthouse 회차가 두 덩어리로 갈렸고, 폰트 응답 470 ms 차이가 점수를 12~15점 흔들었다. 코드 스플리팅의 개선폭(299 ms)보다 컸다.

그때는 폰트 오리진을 차단해 측정만 우회했다. 이번에 원인을 없앴다.

## 무엇을 바꿨나

woff2 **196개(2.92 MB)** 를 저장소에 넣고 `@font-face` 를 직접 선언했다.

| 패밀리 | 굵기 | 파일 | 용량 |
|---|---|---:|---:|
| Gowun Batang | 400 | 95 | 1,554.1 kB |
| Gowun Dodum | 400 | 95 | 1,303.4 kB |
| Judson | 400 · 700 | 6 | 134.9 kB |

**Judson italic 3개는 받지 않았다** — 코드에 사용처가 0건이다 (`font-bold` 15건, italic 0건).

세 폰트 모두 **SIL OFL 1.1** 이라 재배포·웹 임베딩이 허용된다. `OFL.txt` 를 함께 뒀다.

### unicode-range 분할을 그대로 옮겼다

한글은 표현 가능한 글자가 11,172 자라 한 파일에 담으면 1.5 MB 다. Google Fonts 는 글자 범위별로 95조각으로 나누고, CSS 에 **"이 파일은 이 글자들을 담고 있다"** 를 적어둔다. 브라우저는 화면에 실제로 그리는 글자가 속한 조각만 받는다.

전체는 2.92 MB 지만 첫 화면은 **137.8 kB** 만 받는다.

**정적 서브셋(쓰이는 글자만 골라 파일 하나로)은 이 서비스에 쓸 수 없다.** 채팅이라 사용자가 무슨 글자를 칠지 미리 알 수 없고, 빠진 글자는 시스템 폰트로 떨어져 한 문장 안에서 글꼴이 섞인다.

### 배치

`src/fonts.css` 를 `src/index.css` 가 `@import` 한다. **별도 요청이 생기지 않고** 이미 받고 있는 `index-*.css` 안에 들어간다.

`url()` 은 Vite 가 해시 파일명으로 바꿔 `/assets/` 로 내보내므로 서버의 1년 `immutable` 규칙([S10](../s10-cache-headers/README.md))이 그대로 적용된다.

`vite.config.ts` 에 woff2 인라인 금지를 넣었다. 4 kB 미만 서브셋이 3개 있는데 기본 `assetsInlineLimit`(4096) 이면 base64 로 렌더 차단 CSS 안에 박힌다. 33% 부풀고, 조각별로 나눈 의미도 없어진다.

| **LCP** | 3,442 ms | **2,266 ms** | **−1,176 (−34.2%)** |
| **Speed Index** | 4,580 ms | **1,953 ms** | **−2,627 (−57.4%)** |
| TBT | 0 | 0 | — |

### 편차가 사라졌다

| | Before | After |
|---|---|---|
| 점수 회차 | 82 / 82 / **97** / 82 / **97** | 96 / 97 / 97 / 97 / 98 |
| 점수 편차 | **15점** | **2점** |
| FCP 편차 | 1,287 ms | 301 ms |
| SI 편차 | 2,507 ms | 301 ms |

S11 의 이봉분포가 없어졌다. **원인이 외부 폰트 오리진이었으므로 당연한 결과**이고, 이제 다른 변경을 폰트 차단 없이 잴 수 있다.

## 분석 — 바이트가 아니라 타이밍이다

| | Before | After |
|---|---:|---:|
| 폰트 요청 **시작** | 1,268~1,278 ms | **109~139 ms** |
| 폰트 완료 | 2,345~2,365 ms | 1,643~1,707 ms |
| 외부 오리진 요청 | 10건 | **0건** |
| woff2 전송 | 127,862 B (9개) | 137,838 B (9개) |
| CSS 전송 | 44,227 B (2건) | 32,305 B (1건) |
| **전송 합계** | **172,089 B** | **170,143 B** |

**전송량은 거의 같다.** 달라진 것은 폰트가 1,150 ms 일찍 시작해 **첫 페인트 전에 도착**한다는 점이다.

After 는 `Speed Index == FCP` 다 (1,953 == 1,953). 폰트가 이미 있는 상태로 그려져 **FOUT 재페인트가 없다.** Before 는 대체 글꼴로 그렸다가 1,300 ms 뒤에 교체됐고, Speed Index 가 그것을 크게 감점했다.

> woff2 가 10 kB 늘었다. 화면에 그려진 텍스트가 회차마다 조금씩 달라 필요한 조각이 바뀐 결과이며, 같은 9개를 받는다는 점은 동일하다.

## preload 는 넣지 않았다

당초 계획은 self-host 의 이득을 **"`preload` 가 가능해지는 것"** 으로 봤다. 폰트 주소를 우리가 정하니 HTML 에서 미리 요청할 수 있고, 요청 시점을 1,290 ms → 10 ms 로 앞당긴다는 계산이었다.

측정이 이 근거를 무효로 만들었다.

```
폰트 완료 1,643~1,707 ms   <   FCP 1,804~2,105 ms
```

**preload 없이도 이미 첫 페인트 전에 다 도착한다.** 앞당길 여지가 없고, 첫 화면에 필요한 6개 89.5 kB 를 최우선으로 당기면 JS 111 kB 와 대역폭을 다투는 위험만 남는다.

"폰트 요청이 렌더 뒤로 밀린다"는 전제 자체가 외부 오리진을 없애면서 사라졌다.

첫 화면이 필요로 하는 조각은 계산해 뒀다. 나중에 필요하면 근거로 쓴다.

| 텍스트 | 폰트 | 조각 | 크기 |
|---|---|---:|---:|
| `Telepathy` (h1, LCP 요소) | Judson 400 | 1개 | 20,752 B |
| `같은 단어를 떠올린 순간…` | Gowun Dodum 400 | 5개 | 68,764 B |

21글자 문구에 조각이 5개 필요하다. 연속된 한글 음절이 서로 다른 조각에 흩어져 있다.

## 측정 방법 — 브라우저 패인으로는 검증할 수 없었다

빌드 후 브라우저에서 확인하니 **woff2 요청이 0건**이고 `document.fonts.check` 도 `false` 였다. 폰트가 전혀 안 붙은 것으로 보였다.

원인은 코드가 아니라 측정 환경이었다.

```
performance.getEntriesByType('paint')  →  []
document.fonts.size                    →  196   (전부 등록됨)
```

**브라우저 패인이 프레임을 그리지 않아 폰트 요청이 발생하지 않았다.** 폰트는 텍스트가 실제로 레이아웃될 때 요청된다. `document.fonts.load()` 로 강제하니 10개가 정상 수신됐다.

Lighthouse 는 headless Chrome 이 실제로 페인트하므로 이 문제가 없다. **렌더에 의존하는 지표는 렌더가 일어나는 환경에서 잰다.**

## 핵심 지표

| 지표 | 값 |
|---|---:|
| LCP | **3,442 ms → 2,266 ms (−34.2%)** |
| FCP | 3,353 ms → 1,953 ms (−41.8%) |
| Speed Index | 4,580 ms → 1,953 ms (−57.4%) |
| 성능 점수 | 82 → 97 |
| 외부 오리진 요청 | 10건 → **0건** |
| 점수 회차 편차 | 15점 → **2점** |
| 저장소 증가 | **+2.92 MB** (woff2 196개) |

## 남은 것

**저장소가 2.92 MB 늘었다.** 폰트는 내용이 바뀌지 않아 git 이 델타를 다시 저장하지 않지만, clone·빌드 시간에 반영된다.

**Gowun Batang 1.55 MB 가 절반이다.** [S9](../s9-fonts/README.md) 에서 Gowun Dodum 으로 통합하면 `/login` 이 −41% 라는 계산을 남겼다. 통합하면 파일 95개와 `fonts.css` 절반이 함께 사라진다. 세리프를 산세리프로 바꾸는 디자인 변경이라 성능 판단만으로 결정하지 않는다.

**렌더 차단 CSS 가 늘었다** — 16.6 kB → 46.0 kB (gzip). 외부 CSS 27.2 kB 가 없어져 총량은 비슷하지만, 한 파일에 몰렸다. 필요하면 `fonts.css` 를 비동기 스타일시트로 분리할 수 있다. 이번 측정에서는 분리하지 않은 쪽이 더 좋았으므로 그대로 뒀다.

**폰트 갱신 경로가 없다.** Google 이 폰트를 고쳐도 우리 파일은 그대로다. 갱신하려면 받아오는 과정을 다시 밟아야 한다. 대신 주소가 조용히 바뀌어 깨지는 일도 없다.
