# S8. 이미지 자산 — 압축이 듣지 않는 1.4 MB

> 조건: **production build / localhost / 스로틀 없음**
> 측정 대상이 **전송 바이트**이므로 네트워크 스로틀과 무관하다. 시간 지표는 측정하지 않았다.

## 대상 문제

[S7](../s7-compression/README.md) 에서 응답 압축을 적용해 첫 로드 전송량을 70.4% 줄였다. 그때 **압축이 듣지 않는 자산**이 남았다.

| | 자산 성격 | gzip 결과 |
|---|---|---|
| S7 | JS·CSS — 반복 토큰이 많은 텍스트 | −70.4% |
| **S8** | **이미 압축된 이미지 바이너리** | **−4% ~ −27%** |

PNG 는 DEFLATE, JPEG 는 DCT, WebP 는 자체 알고리즘으로 **파일을 만들 때 이미 압축돼 있다.** 압축된 데이터에는 반복 패턴이 남아 있지 않으므로 전송 압축을 한 번 더 걸어도 줄어들지 않는다. 실측하면 PNG 원본 493,961 B → gzip 474,455 B 로 4% 다.

→ **이미지 자체를 바꿔야 한다.** S8 은 이미지 자산 5건을 다시 인코딩한 기록이다.

### 반복된 원인 세 가지

**① 내용에 맞지 않는 포맷.** 흑백 2색 QR 을 JPEG 로, 사진 계열 목업을 24비트 PNG 로 저장했다. 손실 포맷에 선명한 경계를 넣으면 아티팩트가 생기고, 무손실 포맷에 사진을 넣으면 압축이 되지 않는다.

**② 과대 해상도.** 16 px 로 그릴 파비콘에 1633 px 이미지가 들어 있었다.

**③ 래스터를 SVG 로 감쌈.** `favicon.svg` 와 `Halloween.svg` 둘 다 확장자만 SVG 고 내용은 base64 로 인코딩한 PNG·JPEG 였다. SVG 는 텍스트 문서라 바이너리를 담으려면 base64 가 필요하고, 이 과정에서 **정확히 +33.3%** 가 붙는다 (3바이트 → 4글자). 벡터의 이점은 얻지 못한 채 비용만 늘어난다.

## 측정 방법

S7 과 동일하다.

```bash
npm run build && npm start        # production build, localhost:5000

curl -s -H "Accept-Encoding: br, gzip" -o /dev/null -w '%{size_download}' http://localhost:5000<경로>
```

파비콘 Before 는 이전 파일을 `git show origin/v3:...` 로 꺼내 **같은 서버·같은 경로**로 서빙해 측정했다.

렌더 검증은 브라우저 canvas 로 픽셀을 디코딩해 수치로 남겼다. 스크린샷 대신 이 방법을 쓴 이유는 크기·색·알파를 눈이 아니라 값으로 확인할 수 있어서다.

## ① 파비콘 — 659,996 B → 1,150 B

가장 크고, 원인이 셋 다 겹친 사례다.

```
<svg width="1000" height="1000">
  <style> @media (prefers-color-scheme: dark) { ... } </style>
  <g id="light-icon"> <image 472×455  xlink:href="data:image/png;base64,..."/> </g>
  <g id="dark-icon">  <image 998×977  xlink:href="data:image/png;base64,..."/> </g>
</svg>
```

| 구성 | 크기 | 비고 |
|---|---:|---|
| SVG 마크업 | 1,380 B | 전체의 0.2% |
| base64 문자열 | 658,616자 | 전체의 99.8% |
| ├ 라이트 PNG | 52,634 B (472×455) | |
| └ 다크 PNG | **441,327 B (1633×1598)** | 998×977 로 축소 배치 |

탭 파비콘은 CSS 기준 16 px 이다. DPR 3 을 감안해도 48 px 이면 되는데 1633 px 이 들어 있었다 — 필요량의 34배, 픽셀 수로는 1,150배다.

테마 이미지 두 장을 한 파일에 담은 탓에 **라이트 모드에서도 다크용 441 kB 를 함께 받는다.** 파비콘 생성 사이트에 PNG 를 업로드하면 나오는 기본 산출물이다.

### 전송량

| Accept-Encoding | Before | After | 절감 |
|---|---:|---:|---:|
| `br, gzip` | 485,235 B | **666 B** | **−99.86%** |
| `gzip` | 480,200 B | 663 B | −99.86% |
| (없음) | 659,996 B | 1,150 B | −99.83% |

**brotli 가 gzip 보다 컸다** (485,235 vs 480,200, +1.0%). 이미 DEFLATE 로 압축된 PNG 를 base64 로 부풀린 데이터라 두 알고리즘 모두 얻을 게 없고, brotli 쪽 컨텍스트 오버헤드만 남았다. 텍스트 자산에서 brotli 가 유리했던 S7 과 반대 결과다.

```
PNG 원본        493,961 B   ← 이미 DEFLATE 압축됨
  ↓ base64 (+33.3%)
favicon.svg     659,996 B
  ↓ gzip
전송            480,200 B   ← −27%
```

gzip 이 줄인 27% 는 **base64 가 만든 거품**이다. 도달한 480 kB 는 원래 PNG 를 그냥 gzip 한 474,455 B 와 거의 같다. base64 는 8비트 자리에 6비트어치 정보만 담으므로 이론상 최대 75% 까지만 되돌아가며, 실측 72.8% 가 이 값과 맞는다.

### 벡터 재작성 — 시도 4회

파비콘은 벡터 SVG 가 표준이다 (Chrome 80+ · Firefox · Edge 지원, Safari 는 `.ico` 폴백).

| 시도 | 크기 | path | 경로 명령 | 결과 |
|---|---:|---:|---:|---|
| 자동 추적 (라이트) | 11,574 B | 12 | — | 캔버스 전체를 `#000000` 으로 칠하는 path 포함 → **검은 사각형으로 렌더** |
| 자동 추적 (다크) | 215,377 B | 283 | — | 그림자 그라데이션을 15색으로 추적 |
| Figma `PNG to SVG` 플러그인 | 23,132 B | 38 | 직선 1,195 / 곡선 212 | 픽셀 경계를 따라간 다각형 |
| **배경·노이즈 제거 + SVGO** | **1,150 B** | **2** | **직선 13 / 곡선 18** | **채택** |

플러그인 산출물의 직선 1,195개는 픽셀 계단이다. 채택안은 명령 31개로 실제 폰트 아웃라인과 같은 수준이다 (참고: Libre Baskerville `T` 36개, Judson `T` 21개).

### 폰트 아웃라인으로 다시 그리는 안은 기각

로고가 세리프 대문자 `T` + 원 두 도형이므로, 사이트 제목 서체(Judson)의 글리프를 쓰면 완전한 벡터가 된다고 봤다. Judson TTF 에서 `T` 를 추출해 494 B 짜리를 만든 뒤 원본과 픽셀 단위로 겹쳐 일치율(IoU)을 쟀다.

| 후보 | IoU |
|---|---:|
| **채택안 (자동 추적 정리본)** | **91.5%** |
| Libre Baskerville 400 | 82.9% |
| Libre Baskerville 700 | 82.6% |
| Judson 400 | 79.1% |
| Spectral 700 | 76.7% |

Google Fonts 세리프 **26종을 굵기별 49개** 받아 `T` 를 원본 T 의 박스(277×274)에 맞춰 넣고 전부 대조했다. 최고가 82.9% 로 채택안에 못 미친다.

로고의 `T` 는 가로/세로 비가 **1.011** 인데 Judson 은 0.858, 세리프 폰트 대부분이 0.85~0.95 다. Google Fonts 에 없는 서체이거나 손으로 수정한 글자꼴로 보인다.

→ **폰트로 다시 그리면 로고 모양이 바뀐다.** 성능 과제가 아니라 디자인 변경이므로 여기서 멈췄다.

### 파일 2개를 함께 지운 이유

다크 분기를 SVG 안 `@media` 가 담당하므로 `favicon-dark.ico` 가 필요 없고, 크기 대응은 벡터가 하므로 `favicon-96x96.png` 도 필요 없다.

**벡터로 만들면 다크 모드 대응 비용이 이미지 한 장에서 CSS 두 줄(약 150 B)로 바뀐다.** 이번 개선폭의 큰 부분이 여기서 나왔다.

## ② 프로필 이미지 — 86,873 B → 5,796 B (−93.3%)

평면 일러스트인데 24비트 PNG 로 저장돼 있었다. 243×243 은 표시 크기(88 px, ≥1025 px 에서 96 px) 기준 적정이라 **해상도는 유지하고 인코딩만 바꿨다.**

| 후보 | 크기 | PSNR |
|---|---:|---:|
| webp lossless | 55,626 B | ∞ |
| **webp q90** | **5,796 B** | **36.3 dB** |
| webp q85 | 4,514 B | 35.9 dB |
| png 팔레트 | 35,481 B | 46.8 dB |

q90 을 택했다. 표시 크기 88 px 로 축소하면 37.3 dB 이고, 240 px 로 확대해 원본과 나란히 놓아도 차이가 보이지 않는다. **알파 채널은 바이트 단위로 동일하다.**

## ③ Toss QR — 45,150 B → 1,434 B (−96.8%)

QR 은 흑백 2색인데 JPEG 로 저장돼 중간톤 픽셀이 **7.8%** 있었다. 손실 압축이 선명한 경계에 만든 아티팩트다. 임계값 128 로 순수 흑백화한 뒤 팔레트 PNG 로 저장했다.

**결제용이므로 페이로드를 검증했다.** `jsQR` 로 디코드해 원본과 문자열이 완전히 같음을 확인했고, 실제 표시 크기인 200 px 로 축소한 상태에서도 읽힌다.

```
supertoss://send?amount=1000&bank=...&accountNo=...&origin=qr
```

WebP 무손실이 1,154 B 로 280 B 더 작았지만 PNG 를 택했다. 결제 QR 이 인앱 브라우저에서 열리는 경우가 있어 포맷 호환성 쪽을 우선했다.

### `?no-inline` — 인라인 회귀를 막았다

QR 이 4 kB 미만이 되자 Vite 가 base64 로 번들에 넣었다. `LikePage` 에서 두 곳에 쓰여 **3,824 B 가 중복 인라인**됐다.

| | JS 번들 | gzip |
|---|---:|---:|
| 인라인됨 | 551,342 B | 174.44 kB |
| `?no-inline` 적용 | **547,530 B** | **172.33 kB** |

후원 화면에서만 필요한 자산이 모든 방문자의 메인 번들에 얹히는 구조라 별도 파일로 돌렸다. `assetsInlineLimit` 기본값이 4096 B 이므로, **이미지를 줄이다가 이 경계를 넘으면 같은 일이 반복된다.**

## ④ 할로윈 배경 — 358,228 B → 61,450 B (−82.8%)

파비콘과 같은 구조였다. 확장자는 SVG 인데 안에 **2048×1136 JPEG(268,054 B)** 가 base64 로 들어 있었다.

SVG 껍데기를 벗기고 WebP q80 으로 저장했다. 내부 JPEG 대비 PSNR 40.4 dB 다.

해상도는 유지했다 — `background-size: cover` 라 데스크톱 1920 뷰포트를 덮으려면 1946 px 이 필요하다. 1600 px 로 줄이면 42,702 B 까지 가지만 데스크톱에서 확대된다.

`halloween.css` 에서만 참조하고 테마 CSS 는 별도 청크(4.98 kB)라 평소에는 받지 않는다. **체감 개선은 0 이고 전송량 기록으로만 유효하다.**

## ⑤ OG 이미지 — 285,198 B → 72,420 B (−74.6%)

1200×630 목업을 24비트 PNG 로 저장해, 사진 계열인데 무손실이었다. 팔레트 양자화로 줄였다 (PSNR 50.0 dB, 알파 최대차 43).

### 파일명·포맷을 바꾸지 않은 이유

JPEG q85 면 45,381 B 까지 간다. 27 kB 를 더 줄일 수 있는데도 PNG 를 유지했다.

- **URL 안정성** — `og:image` 가 절대 URL(`https://telepathy.my/og-image.png`)이다. 확장자를 바꾸면 이미 크롤링된 미리보기가 재수집 전까지 깨진다.
- **알파** — 픽셀의 **55%(416,007 / 756,000)가 완전 투명**이다. 흰색으로 합성하면 카드 배경이 어두운 플랫폼에서 표시가 달라진다.

크롤러만 받는 자산이라 27 kB 보다 URL·알파 쪽이 값어치가 크다고 판단했다.

## 남은 것

**참조 0건인 파일 4개** — `public/vite.svg`(1,497 B) · `public/icons.svg`(5,031 B) · `src/assets/vite.svg`(8,709 B) · `src/assets/react.svg`(4,126 B). `src/assets/` 쪽 둘은 import 가 없어 번들에 들어가지 않고, `public/` 쪽 둘은 dist 에 그대로 복사된다.

**남은 SVG 3건은 진짜 벡터다** — `remember.svg`(103 kB) · `Emotion_Feedback.svg`(77 kB) · `telpa.svg`(59 kB). 안에 래스터가 없고 path 로 그려져 있어 S8 의 대상이 아니다. gzip 이 60% 이상 듣는다 (103 kB → 39.7 kB). SVGO 로 좌표 정밀도를 낮추면 더 줄지만 효과가 작다.
